# Symptom Decision Table (Common Known Failure Patterns)

> Reference of common known failure patterns across Slurm, `k8s-bridge`, Kueue, and `JobSet`/`Pod` stages. This table is non-exhaustive and may not cover new failure modes after code changes — always verify against live logs, Kubernetes events, and current repository code.

| Observed Slurm Job State & Fields | Root Cause | Diagnostic Check / Next Step |
|---|---|---|
| Rejected client-side with `REJECTION_MESSAGE` from `hack/cli_filter.lua` (`--<opt>` or `heterogeneous job pack_offset=<d>`) | CLI flag is not in `hack/cli_filter.lua` `ALLOWED_OPTIONS` (e.g. `--exclusive`) or heterogeneous job (`pack_offset > 0`). | Remove the unsupported CLI flag from `srun`/`sbatch`/`salloc`, or update `hack/cli_filter.lua` via `dev-slurm-lua`. |
| Unsupported CLI flags (e.g. `--exclusive`) accepted client-side on a bridged partition | Partition is missing from `CliFilterParameters=workload_mixing_partitions=...` in `slurm.conf`, or `deploy/slurm-login-slinky` has stale `/run/slurm/conf/slurm.conf` after `helm upgrade slurm`. | Verify 3-place partition parity and refresh the login pod (`/run/slurm/conf/slurm.conf`) via `infra-configure-crs` (`## 2. Guardrails` & Step 2). |
| `sbatch`/`squeue`/`scontrol` fails with `Unable to contact slurm controller (connect failure)` (`slurm-controller-0` `1/2 Ready`) | `slurmctld` is crash-looping (`job_submit/lua: Unable to stat /etc/slurm/job_submit.lua` when `helm upgrade slurm` omitted `--set-file`; other `fatal:` lines indicate `slurm.conf` syntax/plugin errors). | Check `kubectl -n slurm logs slurm-controller-0 -c slurmctld --previous --tail=50` (and current logs); re-run `helm upgrade slurm` with both `--set-file` Lua flags via `infra-configure-crs`. |
| Rejected by `slurmctld` (client: `Unspecified error`; `slurmctld` logs show `slurm_job_submit` or `slurm_job_modify` error from `hack/job_submit.lua`) | Multi-partition submission including a `WORKLOAD_MIXING_PARTITIONS` partition (`slurm_job_submit`), or non-root job owner modifying/holding a bridged job (`slurm_job_modify` `immutability rule` in `hack/job_submit.lua`). | Submit to a single partition (`--partition=<single-part>`), or cancel and resubmit with desired flags (or have an admin modify the job). |
| Rejected by `slurmctld`: `Invalid generic resource (gres) specification`, `More processors requested than permitted`, or partition state/ACL rejection (no `JOB_ID`) | `GresTypes` lacks `gpu`, `EnforcePartLimits=ALL` rejects jobs against 0 static nodes before dynamic nodes exist, or partition `State`/`AllowGroups` blocks submission (`scontrol show partition <part>`). | Set `GresTypes=gpu` and `EnforcePartLimits=NO` in `controller.extraConf` via `infra-configure-crs`, or inspect `scontrol show partition <part>` (confirm with user before changing partition policy; runtime `scontrol update` does not persist across `slurmctld` restarts). |
| `JobState=PENDING`, `Priority>0` (not held), or `JobState=CANCELLED`, `Comment="JobSet missing"` (`Reason!=JobHeldUser`, bridge logs `JobSet missing for active Slurm job, cancelling job`) | Partition is missing from `WORKLOAD_MIXING_PARTITIONS` on `slurmctld` (`job_submit.lua` never held the job), root ran `scontrol release` on an untranslated held job, or the `JobSet`/`WorkloadMixing` CR was deleted out-of-band after translation. | Verify `WORKLOAD_MIXING_PARTITIONS` parity on `slurm-controller-0` via `infra-configure-crs` (`## 2. Guardrails`). |
| `JobState=PENDING`, `Reason=JobHeldUser`, `Comment` lacks `k8s-bridge-auto-hold` (`AutoHoldMarker` in `translator.go`) | Job was submitted with `--hold`. `k8s-bridge` waits for the user to release the hold. | After user confirmation, run `runuser -u <user> -- scontrol release <JOB_ID>` (returns exit code 1 `ESLURM_REQUESTED_PART_CONFIG_UNAVAILABLE` when 0 dynamic nodes exist, but still sets `k8s-bridge-auto-hold`). |
| `JobState=PENDING`, `Reason=JobHeldAdmin` | Administrator hold is active on the job. | Do **not** run `scontrol release <JOB_ID>` as root if `JobSet/slurm-job-<JOB_ID>` does not exist yet (root bypasses `job_submit.lua`, causing `SlurmJobReconciler` to cancel the job with `Comment="JobSet missing"`). |
| `JobState=PENDING`, `Reason=JobHeldUser`, `Comment` contains `k8s-bridge-auto-hold` | `k8s-bridge` has not translated or unheld the job. | 1. Verify `WorkloadMixing` is `Available=True` (`Available=True` only checks CR existence, not pod readiness; if `ControllerNotFound` or `RestApiNotFound`, align `spec.controllerRef.name` with `kubectl -n slurm get controller,restapi`).<br>2. Verify partition is in `WorkloadMixing.spec.partitionsMapping`.<br>3. Inspect `k8s-bridge-controller-manager` logs for `slurmrestd`/JWT/webhook errors and verify ready pods in `slurm`, `kueue-system`, and `jobset-system`. |
| `JobState=RUNNING` (or `PENDING`) with `Features=(null)` while `k8s-bridge` logs `failed to release hold ... Invalid feature specification` | `SchedulerParameters=ignore_constraint_validation` is missing from `slurm.conf` (`controller.extraConf`), leaving the unheld job unbound to `k8s-id-<jobID>` (`UniqueFeaturePrefix` in `translator.go`). | Restore `SchedulerParameters=ignore_constraint_validation` via `infra-configure-crs` (`## 2. Guardrails`). |
| `JobState=CANCELLED`, `Comment="Translation failed: ..."` (`Reason` remains `JobHeldUser`) | `JobSetTranslator.Translate` (`internal/controller/slurmjob/translator.go`) rejected the job. | Check `Comment` (`scontrol show job <JOB_ID>`) and `JobTranslationFailed` events; update `WorkloadMixing` (`infra-configure-crs`) or job flags. |
| `JobState=PENDING`, `Comment` has `Unheld by k8s-bridge`, `JobSet` has `SUSPENDED=true`, and no Kueue `Workload` exists (or `Workload` has `Admitted=True`) | **No `Workload`:** missing `WorkloadPriorityClass` (`kueue.x-k8s.io/priority-class`), or `JobSet` installed after `Kueue` without controller restart.<br>**`Admitted=True` while `SUSPENDED=true`:** `jobset-system` controller/webhook down. | Check `kubectl get workloadpriorityclass`, `kueue-controller-manager` logs, and `kubectl -n jobset-system get deploy,endpoints`; if `JobSet` was installed after `Kueue`, restart `deploy/kueue-controller-manager` via `infra-deploy-stack` (after user confirmation). |
| `JobState=PENDING`, `Comment` has `Unheld by k8s-bridge`, `JobSet` has `SUSPENDED=true`, and `Workload` has `Admitted=False` (or empty `conditions`) | Waiting for Kueue admission:<br>1. **Pod sizing vs. quota / `LimitRange` (`internal/controller/slurmjob/translator.go`):** `--nodes=min-max` allocates `minNodes` pods; `--ntasks` sets `cpusPerTask=1` (shadowing `--cpus-per-gpu`); memory enforces the `defaultMemoryPerCPUMB` per-CPU floor (static `podTemplate` or `LimitRange` `limits` must cover it); `--overcommit` is ignored (use `sbatch -n1` + inner `srun -n<N> --overcommit`).<br>2. **Queue / flavor / policy blocker:** Inactive `LocalQueue`/`ClusterQueue`, namespace selector or `podTemplate` affinity/taint/`coveredResources`/TAS mismatch, pending `admissionChecks`, or `StrictFIFO` head-of-line blocking. | Inspect `describe workload`, `get jobset -o yaml`, and `ClusterQueue`/`LocalQueue` status. Reshape the job or confirm with user before altering admin queue policies (`queueingStrategy`, `admissionChecks`, `coveredResources`). |
| `JobState=PENDING`, `JobSet` has `SUSPENDED=false`, and `< replicas` (`0` pods created) or `slurmd` pods `Pending` / `ImagePullBackOff` | **`< replicas` pods:** child `Job` `FailedCreate` event in `describe job`.<br>**`Pending` / `ImagePullBackOff`:** insufficient per-node `allocatable` capacity (or missing GPU/DWS tolerations), or unconfigured `DefaultSlurmdImage` (`translator.go`). Pods stuck before `slurmd` starts (`Pending`, `Init:*`, `ImagePullBackOff`) hold Kueue quota indefinitely. | Inspect `describe jobset`, `describe job`, and `describe pod`. If `Insufficient cpu/memory/gpu`, reshape the job (`--nodes` / `--ntasks-per-node`) to fit single-node `allocatable` capacity or report — never create/resize node pools or delete other tenants' workloads without user confirmation. |
| `JobState=PENDING`, `JobSet` has `SUSPENDED=false`, and `slurmd` pods `CrashLoopBackOff` or `Running (0/1 Ready)` | `slurmd` looping `_establish_configuration` retries (`0` restarts under `supervisord`) from missing `slurm.key` or custom `/etc/slurm` `volumeMounts` / `--conf-server` `args` (`translator.go`); `Unable to add node, node table is full` in `slurmctld` logs (`MaxNodeCount` exhausted; `slurmd` registers once at startup and is killed when `startupProbe` expires); or registered `IDLE` node failing `startupProbe`/`livenessProbe` (`translator.go`) while waiting for sibling gang nodes or deferred `StartTime`/`BeginTime`. | Inspect `slurmd` pod logs and `slurmctld` logs; fix `podTemplate` mounts/args or `MaxNodeCount` via `infra-configure-crs`. |
| `JobState=PENDING` (`Reason=BadConstraints`, `Partition*`, `launch_failed_requeued_held`, or `Nodes required for job are DOWN`), `slurmd` pods `Running` (registered in `scontrol show nodes`) or gone | `WorkloadMixing.spec.partitionsMapping[].dynamicNodeFeature` does not match `NodeSet` `Feature` in `slurm.conf` (`TotalNodes=0` in `scontrol show partition`), stale dynamic nodes remain in `slurmctld`, or `scontrol show partition <part>` has `State=DOWN` or `MaxNodes`/`MaxCPUsPerNode`/`MaxMemPerNode`/`MaxTime` caps (`EnforcePartLimits=NO` defers partition limit checks until after dynamic pods register). | Compare `scontrol show node <node>` `ActiveFeatures` against `slurm.conf` `NodeSet` (`infra-configure-crs`), clean up stale dynamic nodes via `ops-cleanup-state`, and inspect `scontrol show partition <part>` (reshape job or confirm before changing admin partition policy; persist changes in `controller.extraConf`). |
| `JobState=FAILED` right after scheduling onto dynamic `slurmd` pod (e.g. `Reason=RaisedSignal:53` / `WTERMSIG 53` in ~1s) | `WorkDir`/`StdOut` directory (default: login submit cwd `/home/<user>`) does not exist on the dynamic `slurmd` pod, or `LD_LIBRARY_PATH` was overwritten by `srun` on a GPU job. | Pass `--chdir=/tmp` (or `-o /tmp/%j.out`, or mount a shared volume in `podTemplate`; note pod and local `StdOut` are deleted ~5s after job end) and `--export=ALL,LD_LIBRARY_PATH=/usr/local/nvidia/lib64` on GPU `srun` jobs (`infra-configure-crs`). |
| `JobState=CANCELLED`, `Comment="JobSet completed"`, `Restarts>=1` (or job never completed) | Dynamic `slurmd` pod was terminated gracefully (`kubectl delete pod`, eviction/drain) or killed by `startupProbe`/`livenessProbe` after sitting `IDLE`/`DOWN` (`scontrol requeue`, dynamic node `State=DOWN`, deferred `StartTime`, or incomplete gang): `supervisord` exited `0`, marking the `JobSet` `Completed` (`translator.go`) and causing `k8s-bridge` to cancel the Slurm job. | Inspect pod/node events and `slurmctld` logs; avoid `scontrol requeue` or `StartTime` deferral on bridged jobs, and resubmit the job. |
| `JobSet` stuck in `Terminating` (`deletionTimestamp` set, `k8s-bridge.x-k8s.io/slurm-node-cleanup` finalizer present) | `k8s-bridge` was uninstalled before `JobSet` finalization completed, `slurmrestd` is unreachable, or the `JobSet` lost its `slurm-job-id` label / `WorkloadMixing` `ownerReferences`. | Check `k8s-bridge-controller-manager` logs for `slurmrestd` errors, or remediate via `ops-cleanup-state` (Step 2). |
| Preempted or queue-stopped job (`Workload` `Evicted=True` with `Preempted` or `LocalQueueStopped`; `JobSet` `SUSPENDED=true` or deleted) | Kueue preempted the workload or `LocalQueue`/`ClusterQueue` transitioned to `HoldAndDrain`. | If `Requeue=1`: Slurm requeues (`PENDING`, `Reason=BeginTime`, `Restarts>=1`, `JobSet` `status.restarts=0`). If `--no-requeue`: Slurm marks `NODE_FAIL` (`Reason=NodeDown`, `Comment` unchanged) and `k8s-bridge` tears down the `JobSet`. |
